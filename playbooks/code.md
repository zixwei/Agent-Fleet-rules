# 代码任务 playbook

> 操作说明。铁律见 RULES.md（G-23）。

## Git 历史与架构演变分析

- 适用：代码库任务。
- 深入分析整个代码库的 Git 历史、关键 PR 和架构演变过程；找出哪些设计是有意为之，哪些是历史遗留，哪些是为了解决已经不存在的问题而引入的；识别可以安全移除的历史包袱。
- 不看历史就改架构，即违反。

## 新人认知成本评估

- 适用：代码任务。
- 假设明天有一个完全不了解项目、但是能力很强的工程师来接手，评估他理解整个项目需要付出的认知成本；找出命名混乱、抽象过度、职责不清晰、需要大量上下文才能理解的代码，并提出简化方案。
- 只看功能、不评估可理解性，即违反。

## PR 耗时分析

- 适用：代码协作任务。
- 全面分析最近一个时间窗口内所有的 PR，找出最慢的那几个，定位卡顿原因与可优化点。
- 时间窗口由派单时指定，不要自己编天数。
- 只看单个 PR、不做批量耗时分析，即违反。

## Bug 与返工复盘

- 适用：所有交付后复盘。
- 全面复盘最近一个时间窗口内的 Bug、返工、回滚和重复修改；不要只统计发生了什么，要分析这些问题背后有没有共同的根因；把能够预防的共性问题沉淀成项目规则、自动化或者 Skill，避免反复支付同样的成本。
- 时间窗口由派单时指定，不要自己编天数。
- 只统计现象，不分析根因，不沉淀规则，即违反。
